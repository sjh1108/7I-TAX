### 1-3. 배포 시 특이사항

#### 아키텍처 개요

```
[클라이언트] → [Nginx:3000] → /api/* → [Spring Boot:18080]
                                     → [AI Service:19000]
[Android App] → https://j14c203.p.ssafy.io/api/ → [Spring Boot]
```

#### Docker 네트워크 구성

- 모든 컨테이너는 `ubuntu_default` Docker 네트워크를 공유
- 컨테이너 간 통신은 컨테이너명으로 접근 (예: `tax-backend`, `tax-ai`)

#### 포트 매핑

| 서비스 | 컨테이너 내부 포트 | 호스트 외부 포트 | Docker 이미지 |
|--------|-------------------|-----------------|--------------|
| Backend (Spring Boot) | 8080 | **18080** | `tax-backend` |
| Frontend (Nginx) | 80 | **3000** | `tax-frontend` |
| AI Service (Uvicorn) | 8000 | **19000** | `tax-ai` |
| PostgreSQL | 5432 | 5432 | - |
| Redis | 6379 | 6379 | - |

#### 볼륨 마운트

| 컨테이너 | 호스트 경로 | 컨테이너 경로 | 용도 |
|----------|-----------|-------------|------|
| tax-backend | `/home/ubuntu/firebase-service-account.json` | `/home/ubuntu/firebase-service-account.json` (read-only) | FCM 서비스 계정 |
| tax-ai | `chroma-data` (Docker Volume) | `/app/data/chroma` | ChromaDB 영속 데이터 |

#### AI 모델 파일

- 빌드 전 AI 분류기 모델을 `/opt/tax7i/models/tax_classifier` 경로에 배치해야 함
- Jenkins 빌드 시 자동으로 `ai/models/tax_classifier/`로 복사됨
- 모델 미배치 시 AI 분류기 없이 동작 (LLM 기반 분류만 사용)

#### 타임존

- Backend 컨테이너: `TZ=Asia/Seoul` 환경변수 설정

#### 배포 순서 (Jenkinsfile 기반)

```
1. BE Docker Build   → tax-backend 이미지 빌드
2. FE Docker Build   → tax-frontend 이미지 빌드
3. Prepare AI Model  → 모델 파일 복사
4. AI Docker Build   → tax-ai 이미지 빌드
5. Deploy            → 기존 컨테이너 정지/삭제 → 새 컨테이너 실행
```

#### Nginx 리버스 프록시 설정 (`FE/nginx.conf`)

```nginx
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # SPA 라우팅
    }

    location /api/ {
        proxy_pass http://tax-backend:8080;  # 백엔드 프록시
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

#### 빌드 알림

- Mattermost Webhook을 통해 빌드 성공/실패 알림 발송

## 3. DB 덤프 파일

- 스키마 파일: `db/init/01_schema.sql` (22개 테이블)
- 시드 데이터: `db/init/02_seed_data.sql`
- DDL 전략: `hibernate.ddl-auto: update` (앱 기동 시 자동 스키마 갱신)
- 별도 DB 덤프 파일이 필요한 경우 `pg_dump` 명령으로 추출:

```bash
pg_dump -h <DB_HOST> -U postgres -d tax_db --no-owner --no-privileges > exec/db_dump.sql
```

## 4. 시연 시나리오

### 시나리오 1: 회원가입 및 로그인

| 순서 | 화면 | 실행 내용 |
|------|------|----------|
| 1 | 스플래시 | 앱 실행 → 스플래시 화면 표시 |
| 2 | 본인인증 (IdentityVerification) | 이름, 주민등록번호 앞자리, 통신사, 휴대폰번호 입력 → "인증 요청" 클릭 |
| 3 | SMS 인증 (SmsVerification) | 수신된 6자리 인증번호 입력 → "확인" 클릭 |
| 4 | 약관 동의 | 필수 약관 전체 동의 체크 → "동의하고 계속" 클릭 |
| 5 | PIN 설정 (PinSetup) | 6자리 PIN 번호 입력 |
| 6 | PIN 확인 (PinConfirm) | 동일한 6자리 PIN 재입력 → 가입 완료 |
| 7 | 가입 성공 (AuthSuccess) | 성공 화면 확인 → "시작하기" 클릭 |
| 8 | PIN 로그인 (PinLogin) | 이후 접속 시 6자리 PIN 입력으로 로그인 |
